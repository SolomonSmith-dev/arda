# AGENTS.md

Guide for coding agents and contributors. ARDA is a multi-agent system behind one FastAPI API and one MCP server: an orchestrator routes each request to a shell executor, a RAG retriever or a chat specialist. Every LLM has a deterministic mock, so tests need no API keys.

## Layout

- `agents/`: one package per agent (orchestrator, shell executor, retriever, chat specialist, scheduler, ops bot); `base.py` holds the `BaseAgent` ABC.
- `core/`: shared config, models, Redis client, logging, shell allowlist policy.
- `api/`: FastAPI app, middleware, routes, public demo mode.
- `mcp_server/`: MCP tools that call the API.
- `evals/`: routing and retrieval gold sets, harness, committed results.
- `tests/`: pytest suite. `scripts/`: `check.sh` (the gate), `run_evals.py`, `update_readme.py`.
- `docs/`: ADRs in `docs/decisions/` and runbooks. `deploy/`: demo deployment files.

## Commands

- Install: `uv sync --extra dev` (slim install, no torch or Milvus; Python 3.12+)
- Test: `uv run pytest tests/ -q`
- Lint: `uv run ruff check .`
- Type-check: `uv run mypy agents core`
- Evals (offline): `uv run python scripts/run_evals.py --mode mock --check --no-write`
- Full gate: `scripts/check.sh` (the same steps CI runs)
- Run the API: `uv run uvicorn api.main:app --port 5000`

## Conventions

- Ruff is authoritative (`E,F,I,B,UP,N,SIM`, line length 100); `from __future__ import annotations` in modules.
- Mock by default: `use_mock_llm` defaults to true and the default test path makes no network calls. Gate live behaviour narrowly in tests.
- Keep the `BaseAgent.run(AgentTask) -> AgentResult` contract and the orchestrator result envelope (`intent`, `specialist`, `specialist_result`) stable; the API and end-to-end tests depend on them.
- Shell commands run only if they match the allowlist in `core/shell_policy.py`, checked at enqueue and again in the worker. Demo mode (`DEMO_MODE=true`) refuses shell execution in the router, the agent and the worker.
- Keep `numpy<2` pinned in `pyproject.toml`: numpy 2.x wheels need CPU features older x86 hosts lack.
- After changing the eval gold set, corpus or mocks, rerun `scripts/run_evals.py` with `--update-baseline` and commit `evals/results/baseline-mock.json`. The README results table is generated by `scripts/update_readme.py`; do not edit it by hand.

## Safety

- Never commit secrets or `.env*` files; use `.env.example` for new settings.
- Examples, fixtures and docs use synthetic data only.

## Done means

`scripts/check.sh` ends with `GATE PASS` (ruff, mypy, pytest, mock evals, README results check). Quote its last lines in the PR. Open a pull request against `main`; do not push to `main` directly.
