# F-3: parameterised Earendil allowlist (`ls -la <path>` under set roots)

Backlog row: `factory/BACKLOG.md` F-3. Owner: the writer agent. Reviewer and QA follow
`factory/AGENTS.md`.

## Goal

Earendil today runs nine exact commands (`core/shell_policy.py`). Add one parameterised form,
`ls -la <path>`, where the path must resolve inside an operator-configured root. Nothing else
becomes parameterised in this task.

## Design

- New setting `earendil_ls_roots: str = ""` in `core/config.py`: colon-separated absolute
  directories. **Empty means the feature is off** and behaviour is identical to today.
- One parser, `parse_command(command) -> list[str]`, used by both `check_command` and
  `argv_for`, so the thing that is checked is the thing that runs. Returns the argv, or raises
  `CommandNotAllowedError`.
- Accept `ls -la <path>` only when all of these hold:
  1. exactly one path argument, after whitespace normalisation;
  2. the path is absolute, contains no `..` component, no NUL, and none of `* ? [ ] { } $ ` ; & | < > \ ' "`;
  3. it does not start with `-`;
  4. `os.path.realpath(path)` is equal to a root, or inside one, compared with a path-aware
     check (`os.path.commonpath` or `Path.is_relative_to`), never `str.startswith`. A root
     `/x/root` must not admit `/x/root-evil`;
  5. each root is itself `realpath`-ed once when read.
- The argv is `["ls", "-la", "--", <realpath>]`. The `--` stops option parsing; the resolved
  path is what gets executed, which shrinks the symlink race to the gap between worker check and
  run (documented, not eliminated).
- Everything that is exact-match today stays exact-match, including bare `ls -la`.
- `EARENDIL_ALLOW_ANY_COMMAND` and demo mode behave exactly as before (demo mode refuses all).
- The worker already re-checks via `check_command`; do not add a second implementation there.

## Acceptance

`tests/earendil/test_shell_policy_params.py` is already in the repo and is the contract.

- The tests marked `xfail(strict=True, reason="F-3 ...")` describe new behaviour. Make them
  pass, then **delete the markers**. Strict xfail makes the gate fail until you do, so the
  markers cannot be forgotten.
- Every other test in that file is a regression guard that passes today and must keep passing.
- `scripts/check.sh` ends in GATE PASS.
- Add `EARENDIL_LS_ROOTS` to `.env.example` (commented) and one sentence to the Earendil line in
  `CLAUDE.md`.
